# Security policy

## Reporting

Do not open a public issue for a suspected vulnerability. Use the repository owner's private security reporting channel configured for the derived project. Replace this paragraph with the real monitored address/process before public release.

Include affected version, impact, minimal reproduction, and safe contact details. Never include live credentials, customer data, or weaponized public exploit steps.

## Supported versions

Versions below `v1.1.1.413` are development-only and receive no supported-release guarantee. Derived projects must maintain a supported-version table before their first release.

## Response expectations

- Acknowledge, classify, contain, remediate, verify, disclose, and document lessons learned.
- Treat leaked credentials as compromised and rotate them.
- Preserve sanitized evidence and correlation IDs; keep raw sensitive evidence outside Git.
- Publish a fixed immutable version; never retag an affected artifact.
